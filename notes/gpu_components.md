## GPU 基础构成

### GPU 是什么

GPU 可以粗略理解成一种为了高吞吐并行计算而设计的处理器。

如果非常粗糙地看，它主要由两部分组成：

1. 计算单元
2. 内存与数据通路

AI infra 里很多问题，不只是“算得快不快”，更是“数据能不能及时送到计算单元”。

### SM 是什么

SM 可以理解成 GPU 上反复复制的“计算核心簇”。

每个 SM 里有：

- 负责执行线程的计算单元
- 寄存器
- shared memory
- 一些调度和控制逻辑

GPU 之所以强，一个重要原因就是它有很多个 SM，可以同时跑大量线程。

### 显存是什么

显存通常指 GPU 板载的大容量内存，现代数据中心 GPU 上通常是 HBM。

它的特点是：

- 容量大
- 带宽高
- 但离计算单元更远，访问代价比寄存器和 shared memory 高

在 CUDA 的语境里，很多时候说的 global memory，底层主要就是走显存这条路径。

显存最适合放：

- 模型权重
- 大张量
- KV cache
- 不能放进片上小内存的数据

### 寄存器是什么

寄存器是离计算单元最近、最快的一层存储。

它的特点是：

- 非常快
- 非常小
- 通常是线程私有

如果一个中间结果能一直放在寄存器里，访问成本最低。  
但寄存器数量很有限，所以寄存器不够时，性能就可能受影响。

### local memory 是什么

`local memory` 这个名字非常容易误导。

它不是“离线程很近、很快的小内存”。  
在 CUDA 语境里，`local memory` 指的是：

- 逻辑上属于某个线程私有
- 但物理上通常不在寄存器里
- 往往最终还是走显存路径

它常见于这些情况：

- 一个线程需要的临时变量太多，寄存器装不下
- 使用了编译器无法完全放进寄存器的数据结构
- 某些数组或局部对象需要被溢出到更慢的存储

所以它最重要的特点不是“local”，而是：

- 线程私有
- 但不快

如果程序里大量数据落到 local memory，通常意味着：

- 寄存器不够了
- 访问代价会变高
- 性能可能会明显下降

所以从性能角度看，`local memory` 常常更接近“线程私有但很慢的存储”，而不是“线程自己的高速缓存”。

### shared memory 是什么

shared memory 是位于 SM 上的一块小而快的内存。

它的特点是：

- 比显存快得多
- 容量比显存小很多
- 一个 thread block 内的线程可以共享访问

它常见的用途是：

- 把会被重复使用的数据先搬进来
- 减少反复访问显存
- 重排访问模式，让访问更高效

你可以把它粗略理解成“程序员可控的小缓存”，但它不等于自动缓存。

### L2 cache 是什么

L2 cache 是 GPU 上更大一级的缓存层，位于 SM 外，但仍然比显存更近。

它的特点是：

- 比 shared memory 慢，但通常比直接打到显存更快
- 容量比 shared memory 大
- 对多个 SM 更共享

L2 cache 的作用是：

- 缓冲最近访问过的数据
- 降低直接访问显存的次数

但它通常是硬件管理的，不像 shared memory 那样由程序员显式控制。

### shared memory 和 L2 cache 的差别是什么

最核心的差别是：

- shared memory：程序员显式管理，作用域更局部，更快，更小
- L2 cache：硬件自动管理，作用域更全局，更大，但不如 shared memory 可控

### 显存、L2、shared memory、寄存器的关系

从“离计算单元远近”和“大致速度”上看，可以粗略记成：

1. 寄存器：最近、最快、最小
2. shared memory：很近、很快、很小
3. L2 cache：更大、更共享、速度居中
4. 显存（HBM / global memory）：最大、最远、访问代价最高

这不是精确教材定义，但很适合先建立直觉。

### 为什么这几层这么重要

因为很多 GPU 性能问题，本质上就是：

- 数据是不是反复从慢层读取
- 数据能不能被复用
- 访问模式是不是高效
- 计算单元有没有被喂饱

所以你以后看到很多优化，本质都在做下面几件事：

- 尽量多用寄存器
- 尽量把复用高的数据放进 shared memory
- 尽量让访问模式友好，提升 cache 和带宽利用率
- 尽量减少直接访问显存的压力

## 当前最容易混淆的点

- `global memory` 不等于“某种特别抽象的逻辑空间”，在性能讨论里它经常可以近似理解成走显存路径
- `local memory` 虽然名字叫 local，但不是“又近又快”的意思
- `shared memory` 不是 cache，而是显式管理的小内存
- `L2 cache` 不是 shared memory，也不是显存
- “显存大”不等于“memory-bound 问题就解决了”，很多时候卡的是带宽和访问模式
